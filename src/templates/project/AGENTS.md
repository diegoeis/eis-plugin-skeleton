## Where things live

- `src/` is the plugin root. Only what is here goes into the package. Plugin files (skills, agents, hooks, `.mcp.json`) always go inside `src/`, following the standard layout: https://code.claude.com/docs/en/plugins-reference#standard-layout
- `src/.claude-plugin/plugin.json` is the manifest and the single source of the version (the `version` key).
- `docs/` holds specs, decisions and project documentation. Nothing here goes into the package.
- `scripts/` holds project scripts. `pack.sh` packages the plugin; `pii-patterns.txt` lists patterns that must not appear in `src/`. It is local and stays out of git (the versioned template is `pii-patterns.example.txt`). Never copy its contents into versioned files.
- `dist/` is generated by `scripts/pack.sh` and stays out of git. Don't edit anything there.
- `AGENTS.md`, `CLAUDE.md` and `README.md` live at the project root, never in `src/`. A `CLAUDE.md` at the plugin root isn't loaded as context and makes `claude plugin validate` warn.

## Rules

- Don't create project files (notes, drafts, specs) inside `src/`.
- For every new package (after the first), bump `version` in `src/.claude-plugin/plugin.json`. `pack.sh` refuses a version that already exists in `dist/`.
- To package, run `./scripts/pack.sh` from the project root.
- To test locally without packaging: `claude --plugin-dir ./src`.
- Check the official plugin documentation before creating components: https://code.claude.com/docs/en/plugins-reference
